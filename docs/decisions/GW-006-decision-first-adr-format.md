# GW-006 — ADRs lead with the ruling, not the story
Status: accepted · 2026-08-20

**Ruling**: Every ADR gets a mandatory 3-line **Ruling**/**Because**/
**Enforced by** header after the title/status line, then a `---` fold before
unbounded narrative. Each repo also gets `specs/decisions/INDEX.md`, one line per ADR.
**Because**: most readers of an ADR — every future session included — need
only the current rule, not the incident that produced it, and today's format
makes them read the whole file to get it.
**Enforced by**: `docs/groundwork.md` § ADR format (advisory); repos with an
eval harness add an invariant-suite case checking every ADR has a
`**Ruling**:` header ≤3 lines and INDEX.md has exactly one line per ADR file.

---

## Context

groundwork's own ADRs (GW-000 through GW-004) and the format GW-000
prescribed for descendants ("Context, Decision, Consequences") both mix the
ruling with the narrative that produced it. Reading GW-002 to answer "what's
the scope-boundary rule right now" requires reading the M8 incident
paragraph, the four numbered decisions, and the consequences section — the
ruling is recoverable but not extractable at a glance. This cost is paid
every time an agent enters a repo and needs "what are the current rules"
(`docs/groundwork.md` step 5 already tells agents that a judgment call about
correctness becomes an ADR — but never told them how to *read* one fast).
GW-005, written the same day, is the first ADR to actually need this: it
amends two prior ADRs' round-comment format, and a reader needs to be able
to tell "amends" from "still true" without diffing prose paragraphs.

## Decision

Split every ADR into two zones divided by a `---` fold line:

```markdown
# ADR-013 — <the ruling itself as one sentence, not a topic name>
Status: accepted · <date> · Amends: ADR-007 (if any)

**Ruling**: what is now true, 1–3 lines, imperative.
**Because**: the core reason, one line.
**Enforced by**: case ids / hook / code location — or `advisory — <where it
binds>` if genuinely unenforced.

---
(unbounded: Context, Evidence, Alternatives rejected, Consequences)
```

The header is a hard size cap (title is the ruling restated as a sentence,
not a topic label; Ruling ≤3 lines) — the point of the format fails if the
header itself grows into a summary paragraph. Everything that isn't the
ruling — the incident, the evidence, the roads not taken, the fallout — goes
below the fold, unbounded, exactly as before.

Each repo also gets `specs/decisions/INDEX.md`: one line per ADR
(`ADR-013 — <ruling sentence> — enforced by <x>`), with superseded/amended
ADRs marked. INDEX.md is the fast digest; the header is the per-file digest;
the fold is the archive. groundwork's own series gets the same treatment at
`docs/decisions/INDEX.md` (GW-numbered).

Maintenance is gated, not disciplined, matching GW-000's founding principle
(advice doesn't bind agents, enforcement does): a repo with an eval harness
adds an invariant-suite case that fails if any ADR lacks a `**Ruling**:`
header ≤3 lines, or if INDEX.md's line count diverges from the ADR file
count. groundwork itself has no eval harness (docs/decisions/ regenerates the
header, never a decorative invariant it can't check) — for groundwork the
rule stays advisory, checked by hand at header-retrofit time; the case
applies once a project instantiates the template.

## Alternatives rejected

- **Separate ADR-summary index file with the header content, ADRs unchanged.**
  Rejected: doubles the source of truth — the index would drift from the ADR
  body the moment someone edits one and not the other. The header lives
  inside the ADR it summarizes; INDEX.md is generated by hand from headers,
  not an independent record.
- **Structured frontmatter (YAML) instead of a prose 3-line header.** Rejected
  as unnecessary machinery for a document meant to be read by a human or an
  agent's context window, not parsed by a program beyond a regex header
  check — plain markdown bolded fields stay grep-able and need no schema.
- **No header, just tell readers to skim to Decision.** This is roughly the
  status quo, and GW-002 is the counter-example: 47 lines before a reader
  reaches something ruling-shaped, no size bound on it once reached.

## Consequences

- Every existing ADR needs retrofitting once (additive: header inserted, the
  original content moves below an added `---`, never rewritten). GW-000
  through GW-006 are retrofitted in this same change.
- New ADRs cost one extra drafting step (compress the ruling into 3 lines)
  before the narrative is written — in practice this is often easier to
  write first, since it forces the actual decision to be stated before its
  justification.
- INDEX.md is one more file to keep in sync per repo; the invariant-suite
  case is what keeps it from rotting the way `tasks/TODO.md`'s Done section
  did before GW-004.
